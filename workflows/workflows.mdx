The **Workflows** page at `/workflows` is the index for durable development automations. It has two tabs: **Workflows**, the definitions you have authored, and **All runs**, every execution across every workflow.

A workflow is a typed graph — one trigger, then steps connected by handles — that the control plane executes durably. A run survives a control plane restart, an agent restart, and a dropped connection, picking up from the last completed step rather than starting over.

## Workflows tab

Each workflow shows its name, description, enabled state, version count, and run count. A badge pairs its overlap policy with the [scope](/workflows/workflow-edit#overlap-scope) that policy is measured in — *Queue · Per worktree*, for instance. It also shows **Quick actions** when the workflow appears as a button elsewhere in the app and **Reserves worktree** when its runs use exclusive worktree admission.

| Action | Effect |
| --- | --- |
| **Run** | Starts a run of the published version |
| **Edit** | Opens the [workflow editor](/workflows/workflow-edit) |
| **Duplicate** | Copies the definition into a new draft workflow |
| **Enable** / **Pause workflow** | Controls whether triggers can start runs |
| **Archive** | Hides the workflow from the active view without deleting it |
| **Export** | Downloads the definition as a file |

Clicking anywhere on a card opens that workflow. The name, the menu, and the links inside the card keep their own behavior.

**New workflow** opens the editor on a blank canvas. **Import** loads exported definition files back in as drafts — the round trip is how you move a workflow between control planes.

### Managing workflows

**Edit** turns on selection on this tab. In selection mode a card toggles instead of opening, and each card header carries a checkbox.

- **Select all** picks up every workflow matching the current search.
- **Export** downloads one `<name>.workflow.json` file per selected workflow.
- **Delete** permanently removes the selected workflows.

<Warning>
  Deleting a workflow is permanent. A workflow that has run history cannot be deleted — archive it instead. Deleting a mixed selection removes what it can and reports what stopped it.
</Warning>

### Importing several files

**Import** accepts more than one file at a time. A single file opens straight in the [workflow editor](/workflows/workflow-edit); several files import in place and the new cards appear on this tab. Each file is handled on its own, so one unreadable file names itself in the error banner rather than costing you the rest of the batch.

<Note>
  Enabled and published are different things. A workflow must be **published** to have an immutable version to run, and **enabled** for its triggers to fire. Pausing leaves the published version intact and simply stops new runs.
</Note>

## All runs tab

A table of every run with its number, workflow, status, trigger, agent, worktree, and start time. The agent and worktree cells link straight to those pages; a run that targeted neither shows an em dash.

<AccordionGroup>
  <Accordion title="Run statuses" icon="chart-line">
    | Status | Meaning |
    | --- | --- |
    | Queued | Accepted, but waiting for workflow capacity or worktree admission |
    | Running | Executing steps |
    | Waiting | Held on a delay, a wait-until, or an external condition |
    | Blocked | Cannot proceed — usually missing or invalid session data |
    | Pausing / Paused | Pause requested, then honored |
    | Succeeded | Reached a terminal step with no failure |
    | Failed | A step failed under a **Fail workflow** policy |
    | Cancelled | Stopped by hand |
  </Accordion>
  <Accordion title="Generations" icon="code-branch">
    Replaying a run does not rewrite history. It opens a new **generation** that appends fresh step attempts alongside the originals. The generation is not a column here — open the [run](/workflows/workflow-run) to see which pass produced a result.
  </Accordion>
</AccordionGroup>

### Managing runs

- **Edit** turns on selection. Select individual runs, everything from a day, or **Select all**.
- With a selection, **Archive** (or **Restore**, when viewing archived) and **Delete** apply in bulk.
- The **Archive filter** switches between **Active**, **Archived**, and **All**.

<Warning>
  Deleting a run removes its full step history permanently. Archive instead when you only want it out of the way.
</Warning>

## Search and refresh

The search box filters across both workflows and runs. On **All runs** it covers the run number, workflow name, status, trigger, and the run's worktree branch, folder, and agent name. **Refresh** refetches the current tab.

## Quick actions

A workflow can surface as a button on the pages of the resources it operates on — a worktree, a pull request, a GitHub Actions job. The action shows up only when the workflow is **published**, **enabled**, and carries a resource trigger whose action type matches. Configure this on the [workflow details page](/workflows/workflow-detail).

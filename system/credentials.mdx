The **Credentials** page at `/credentials` reviews the active credential backend and gives a metadata-only inventory of stored secrets. Secret values are never shown here.

## Using the page

- Review the active **Backend** (database, HashiCorp Vault, or macOS Keychain), its **Protection** status, and any warnings.
- Inspect the **Stored credential items** table — owning feature, credential kind, and updated time.
- Manage each value in its owning settings form; this page is read-only.

## What is stored here

Long-lived Jira, GitHub, cache-server, external MCP, iOS-signing, App Store Connect, and APNs credentials all go through this server-only credential service. Pick a backend with `CREDENTIAL_STORAGE_TYPE` — see [Set up credential storage](/quickstart#set-up-credential-storage) for the configuration of each one.

## Vault options

Beyond `VAULT_ADDR`, the Vault backend accepts `VAULT_TOKEN`, `VAULT_NAMESPACE`, `CREDENTIAL_VAULT_MOUNT` (default `secret`), `CREDENTIAL_VAULT_PATH_PREFIX` (default `ai-development-environment/credentials`), and `CREDENTIAL_VAULT_HEADERS`.

`CREDENTIAL_VAULT_HEADERS` must be a JSON object of string values, and should be shell-quoted:

```bash
CREDENTIAL_VAULT_HEADERS='{"X-Vault-AWS-IAM-Server-ID":"vault.example.com"}'
```

Custom headers cannot override transport-managed headers or conflict with `VAULT_TOKEN` and `VAULT_NAMESPACE`.

TLS options are `VAULT_CACERT`, `VAULT_TLS_SERVER_NAME`, and `VAULT_SKIP_VERIFY`. Plaintext HTTP and disabled certificate verification are supported, but produce prominent security warnings.

## Switching backends

Each metadata row records the backend that received its payload. Changing `CREDENTIAL_STORAGE_TYPE` does not migrate, read, or delete values from the previous backend: mismatched items are reported and must be re-entered through their owning settings forms.

<Warning>
  Backend-to-backend migration and encryption key rotation are intentionally unsupported.
</Warning>

## Notes

- Secret values, ciphertext, authentication headers, and secret-derived previews are never returned to the browser.
- The backend is selected with the `CREDENTIAL_STORAGE_TYPE` environment variable.
- Vault and Keychain outages do not take down the dashboard; only the features that need an unavailable credential fail.
- The `keychain` backend is loaded only on Darwin. Selecting it on Linux or in a container leaves the app running and reports an unsupported-backend error.

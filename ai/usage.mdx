The **Usage** page at `/usage` answers "what have my AI tools actually cost?" across every Mac you manage. It does not read a stored table — each visit fans a collection job out to your online agents, runs `ccusage --json` on each of them, and aggregates the reports into one view broken down by day, model, and Mac.

<Note>
  This page reports what the AI tools themselves recorded on disk, covering all local usage including work you did outside this control plane. The per-run figures on a [Plan](/ai/plan-detail) or [Session](/ai/session-detail) come from the run's own token counts instead — the two answer different questions.
</Note>

## How collection works

<Steps>
  <Step title="The request fans out" icon="share-2">
    Opening the page starts a collection against every enrolled agent. Agents that are offline, or whose `control-agent` build does not advertise the ccusage capability, are excluded from the eligible set and named in the status banner.
  </Step>
  <Step title="Each agent runs ccusage" icon="terminal">
    A job runs `ccusage --json` locally, with a 120-second timeout and a 16 MB cap on output. Results stream back as each Mac finishes.
  </Step>
  <Step title="Reports are merged" icon="layers">
    Daily entries from every Mac are merged by date, then by model, then by agent. The whole collection has a 150-second deadline; whatever has reported by then is what you see.
  </Step>
  <Step title="The page updates live" icon="refresh-cw">
    Progress arrives over a subscription and is reconciled every two seconds until the collection completes. **Refresh usage** discards the result and starts a fresh collection.
  </Step>
</Steps>

The status banner above the results always shows ***n* of *N* compatible agents reported**, and lists offline Macs, Macs needing a `control-agent` update, and any that failed with their error text.

## Reading the results

| Element | What it shows |
| --- | --- |
| **Daily cost by model** | Stacked USD per day across the selected range. Selecting a model in the legend charts it alone; selecting it again restores every model |
| Summary tiles | Total cost, total tokens, input, output, cache creation, and cache read for the current filters |
| Usage table | One row per day, expandable to models, expandable again to the Macs that used each model |
| Grand total | The table footer, covering the selected range |

Each agent row inside the table also names the sources ccusage attributed that usage to, so you can see which tool on that Mac spent the tokens.

<Note>
  A day can carry an **Unattributed tokens** row. That is usage ccusage recorded without a model attached — it counts toward totals but cannot be charted against a specific model.
</Note>

## Filters

- **Range** — **All data**, **7 days**, or **30 days**.
- **Agent** — appears once more than one Mac has reported, and narrows every chart, tile, and table row to that Mac.
- **Model** — set by selecting a model in the chart legend. The summary tiles say so explicitly when they cover one model rather than the whole range.

Selecting a model and then narrowing the range past the point where that model appears drops the model filter rather than showing a row of zeros.

## Empty states

The page distinguishes several kinds of "nothing here", so the fix is never a guess:

| Message | What to do |
| --- | --- |
| **No agents enrolled** | Enroll a Mac from the [Agents](/agents/agents) page |
| **No agents online** | Connect an enrolled Mac and refresh |
| **No compatible agents online** | Update `control-agent` on an online Mac to pick up the ccusage capability |
| **Usage collection failed** | No agent returned a valid report — check the per-agent errors in the banner |
| **No usage found** | Agents reported successfully but ccusage has no daily usage recorded |
| **No usage in this range** | Widen the range to reach older usage |

## Notes

- Nothing is cached between visits: every load is a fresh collection, so the figures always match what is on disk right now.
- `ccusage` must be installed and on the agent's `PATH`. A Mac that cannot run it reports a failure rather than silently contributing zero.

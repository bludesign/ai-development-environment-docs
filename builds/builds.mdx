The **Builds** page at `/builds` holds iOS build history and the reusable JavaScript hooks that run around each build. It has two tabs: **History** and **Build Scripts**.

Builds themselves are started from a worktree, not from this page — see [Worktrees](/worktrees/worktrees).

## History

Every build record, newest first, with its status, destination, duration, and artifact count.

| Status | Meaning |
| --- | --- |
| Queued | Accepted, waiting for the agent |
| Preparing | Setting up the build folder and environment |
| Running | `xcodebuild` is executing |
| Succeeded | Completed with no failure |
| Failed | The build or a script failed |
| Canceled | Stopped by hand |

Filter by status, select builds individually or a whole day at once, and **Delete selected**. The list pages with **Load more**.

<Warning>
  Deleting a build permanently removes the build record *and* its build folder — logs, products, archives, and exports. There is no undo.
</Warning>

## Build Scripts

Reusable pre-build and post-build hooks that run around every build that selects them.

| Field | Notes |
| --- | --- |
| **Name** | How the script appears when selecting scripts for a build |
| **Pre-build JavaScript** | Default-export a function receiving `buildId`, `branch`, `destination`, `action`, and the telemetry URL snapshot |
| **Post-build JavaScript** | The same, plus `buildFolder`, `failed`, `cancelled`, `errorCode`, and `error` |
| **Timeout in seconds** | How long a hook may run |
| **Failure behavior** | **Fail the build** or **Continue with a warning** |
| **Preselect this script for builds** | Marks it enabled by default when starting a build |

<Warning>
  Build scripts are trusted Node.js ESM code. They run from the selected worktree root with a minimal environment, with the permissions of the agent account — treat them like any other code you would run on that Mac.
</Warning>

<Note>
  Creating a script here does not make it run anywhere. A script has to be allowed for a repository on that repository's [details page](/codebases/repository-detail) before a build in that repository can select it.
</Note>

## Worktree coverage

**Run Worktree Coverage** runs tests with coverage and measures the executable lines changed in the current branch and working tree — a coverage number scoped to the change rather than the whole project. Reports appear on the [worktree details](/worktrees/worktree-detail) page.

## Notes

- Build records are immutable. Each build gets its own folder for logs, products, archives, and exports, so two builds never overwrite each other's output. The folder location is set per agent under **Builds directory** on the [agent detail page](/agents/agent-detail).
- Successful builds that produced a runnable app and have never been deployed surface in the [Action Center](/dashboard) as **Ready to run**.

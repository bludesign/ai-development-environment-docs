The **Apps** page at `/dashboard/apps` groups repositories into the products they support. An app can contain one repository or several. The same repository can belong to more than one app.

Apps do not replace repositories. A repository still owns its checkouts and repository-level settings. An app gives you a central, filtered view of the development resources that use its assigned repositories.

## Using the page

Each card shows the app description, assigned repositories, and resource counts. Select the card or **Open app** to open the app hub.

### Card counts

| Counter | What it includes |
| --- | --- |
| **Dirty worktrees** | Visible worktrees with staged or unstaged changes. Appears only when the count is greater than zero. |
| **Worktrees** | All visible primary and linked worktrees in the app's assigned repositories. |
| **Worktrees off main** | Visible worktrees on a named branch other than the literal `main`. Detached worktrees and unknown branch names are excluded. A branch named `master` contributes to this count. |
| **Open PRs** | Distinct open pull requests and merge requests linked to visible worktrees, including drafts. The same request is counted once across multiple checkouts. |

Counts span the app's assigned repositories and their agents. They use the worktree and linked request status last stored by the control plane. Use **Refresh request** on a [worktree](/worktrees/worktrees) to refresh its pull or merge request status.

Select any count to open the app's **Worktrees** view with its saved filters.

### Create an app

<Steps>
  <Step title="Open the editor">
    Click **Create app**.
  </Step>
  <Step title="Describe the app">
    Enter a unique name. Names are case-insensitively unique. Add an optional description to explain the product or service boundary.
  </Step>
  <Step title="Assign repositories">
    Select at least one repository. You can assign a repository that is already used by another app.

    When the list is long, check one or more agents under **Agents** first. The repository list then shows only the repositories checked out on those agents. The agent selection is a saved view filter — it is restored the next time you edit the app, but it never changes what is assigned. Repositories you already selected stay assigned even while the filter hides them, and the editor says how many.
  </Step>
  <Step title="Save the app">
    Click **Create app**. The app appears immediately and stays synchronized through live updates.
  </Step>
</Steps>

<Note>
  You can register existing checkouts from [Codebases](/codebases/codebases), or use **Import** to create repositories from an exported package and clone them onto selected agents. The **Create app** button stays disabled until at least one repository exists; **Import** remains available.
</Note>

## Import or export an app

Click **Import** to open a portable app or repository package. Choose the contents, select destination agents, and review existing values and conflicts before saving. Each selected missing repository is cloned beneath the destination agent's **Base repository directory**.

To export an existing app, open its details and click **Export**. You can exclude individual repositories, settings, preparations, commands, workflows, and other included configuration before downloading the JSON package. See [Import and export](/apps/import-export) for the shared review flow and dependency mapping.

## Shared repositories

A shared repository contributes its resources to every app that includes it. For example, a web repository used by both a customer portal and a mobile product appears in both hubs. Removing it from one app does not remove it from the other app.

## Notes

- MCP clients can use `get_apps` and `get_app` to read app names, descriptions, selected agent IDs, repository IDs, and resource counts. These read-only tools omit nested agent configuration. Add them to an [MCP preset](/system/tools#mcp-tool-presets) to make app discovery available to a run.
- App assignments are many-to-many. An app can contain many repositories, and a repository can belong to many apps.
- Card counts exclude hidden worktrees. The app hub's **Overview** also shows plan and session totals, which exclude archived runs.
- **Create app** only groups existing repositories. **Import** and the app's **Sync** view can create missing checkouts on selected agents.

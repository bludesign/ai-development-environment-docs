The **Commands** page at `/commands` is where you save shell commands you run often and review every execution of them. It has two tabs: **Runs**, the durable history, and **Definitions**, the saved commands themselves.

A command run is durable. The script executes as an agent job, output is retained, restarts are handled by policy, and the run keeps an immutable snapshot of exactly what was executed — so history stays accurate even after you edit the definition. A concurrency mode decides whether it starts immediately or waits for other command runs on the same target.

<Warning>
  Commands run with the full permissions of the selected agent account. Anyone who can reach the control plane can run them on the machines you have enrolled.
</Warning>

## Definitions tab

Each saved command shows its name, description, target scope, and a **Quick action** marker when it is configured to appear as a button elsewhere.

- **New command** opens the [command editor](/commands/command-new).
- **Run** launches it. If the target scope is broad — any agent home, any worktree — you are asked to pick the concrete agent or worktree first.
- **Edit** opens the [edit page](/commands/command-edit).
- **Archive** removes it from the active view while keeping its run history.

### Managing definitions

**Edit** turns on selection on this tab. Clicking anywhere on a card selects it, and the checkbox in each card header does the same.

- **Select all** picks up every command matching the current search.
- **Export** downloads one `<name>.command.json` file per selected command.
- **Delete** permanently removes the selected commands.

<Warning>
  Deleting a command is permanent. A command that has run history cannot be deleted at all — archive it instead, which keeps the history intact. Deleting a mixed selection removes what it can and reports what stopped it.
</Warning>

## Import and export

A command travels between control planes as a JSON file. **Export** writes it; **Import** reads it back.

**Import** accepts several files at once. Importing a single file opens it straight in the [command editor](/commands/command-edit); importing several stays on the **Definitions** tab, where the new cards are the result. Each file is handled on its own, so one unreadable file names itself in the error banner rather than costing you the rest of the batch.

<Note>
  Agent and repository identifiers are specific to one install, so a scoped command travels by target *name*. If the importing control plane has no agent or repository by that name, the target widens — **This agent's home** becomes **Any agent home**, and **This repository's worktree** becomes **Any worktree** — and the quick action is switched off, since running the script anywhere is a decision for whoever imported it.
</Note>

An exported file carries the command's name, description, script, target, restart policy, quick action settings, and notification setting. A hand-written file containing just those fields imports as well, without the export envelope.

## Runs tab

A table of every run with **Run** number, **Command**, **Status**, **Agent**, **Worktree**, **Started**, and **Finished**.

| Status | Meaning |
| --- | --- |
| Queued | Accepted, waiting for its target, predecessor, restart delay, or agent |
| Running | Executing |
| Restarting | Exited and waiting on the restart policy |
| Cancelling | Termination requested |
| Succeeded | Exited cleanly |
| Failed | Exited non-zero, or restarts were exhausted |
| Cancelled | Terminated by hand |
| Timed out | Exceeded its job timeout |

Each run also records its **origin** — **Manual**, **Quick action**, **Workflow**, or **Rerun** — so you can tell who or what started it.

### Managing runs

- Filter by **Active**, **Archived**, or **All**, and search across commands.
- **Edit** turns on selection; select individual runs, everything from a day, or **Select all completed runs**.
- With a selection, **Archive**, **Restore**, or **Delete** in bulk.
- Per run, **Rerun** starts a fresh run from the same snapshot, and **Terminate** stops an active or queued one.

<Warning>
  Deleting runs permanently removes them along with all retained terminal output. Only completed runs can be selected for deletion.
</Warning>

## Running a one-off command

**Run custom** executes a script without saving a definition. Choose where it runs, paste the script, and go. The run is still durable and still retained in immutable history — it just has no reusable definition behind it. Custom runs use non-exclusive concurrency.

## Quick actions

A saved command can be surfaced as a button on the pages of the things it targets: agent-home commands appear on the [Agents](/agents/agents) page and agent detail, and worktree commands appear on worktree pages. Configure the icon and button style when you create or edit the command.

When the command has active runs on that target, a spinner menu appears beside its button. The menu lists every active run and lets you **Terminate**, **Restart**, or **View** it. Select the command button again to start another run; its concurrency setting decides whether it starts or queues. **Restart** terminates the selected run and creates a successor from its snapshot. The successor waits for the original to finish.

## Notes

- Scripts run through the agent user's non-interactive login shell. Interactive input and PTY applications are not supported — a script that waits for a prompt will hang until it times out.
- On macOS and Linux, an agent terminates command process groups left by an earlier instance of the same enrollment before it claims new work. It sends `SIGTERM`, waits five seconds, then uses `SIGKILL` if needed. Other agent enrollments under the same operating-system account are not affected.
- Older agents may not advertise the saved-command capability. The UI offers **Upgrade agent** rather than letting you launch against a target that cannot run it.
